# Personal Memory Agent Architecture Design

## 1. Overview

### 1.1 Project Vision

本系统旨在构建一个 Personal Memory Agent，用于帮助用户从长期日记、聊天记录、笔记等个人数据中进行高质量记忆召回、回忆重构以及自我反思。

与传统 RAG 系统不同，本系统不直接对原始文本进行 embedding 检索，而是引入 Memory Representation Layer，将原始经历转化为多视角语义表示（Memory Views）。

核心思想：

> Memory is not stored as text.  
> Memory is stored as meaningful representations of experiences.

---

### 1.2 Design Goals

系统目标：

1. 支持长期、大规模个人数据存储
2. 支持开放式自然语言回忆查询
3. 支持抽象概念检索，例如：
   - 我什么时候开始变得自律？
   - 我什么时候开始接受失败？
   - 哪些经历影响了我的价值观？
4. 支持 Memory Evolution：
   - 新经历不断加入
   - 对已有认知进行更新
   - 形成用户长期模型

# 3. Core Concept

## 3.1 Memory Unit

系统中的最小检索单位不是 Chunk。

而是：

> Memory View

一个 Chunk 可以产生多个 Memory View。

Example:

Original Diary:

```text
今天练习英语书法。

一开始觉得游丝和单词宽度很难控制。

但是想到她练习 ES 小棒的时候也经历过类似阶段。

最终完成今天三件事情。

感觉自己可以慢慢成长。
```

生成：

```text
Chunk ID: 10001

View 1
Type:
Event

Content:
今天完成英语书法练习，并建立每日任务。

----------------

View 2
Type:
Growth

Content:
作者开始接受能力提升需要时间，
不再因为短期困难否定自己。

----------------

View 3
Type:
Identity

Content:
作者正在形成通过持续行动建立自我信任的模式。

----------------

View 4
Type:
Future Query

Content:
未来可能会询问：
什么时候开始接受成长需要时间？
什么时候形成长期主义？
```

# 4. Memory View Design

## 4.1 View Types

系统不采用固定字段 Schema。

采用动态 View。

推荐初始 View 类型：

### Event View

描述：

发生了什么。

Example:

```text
今天完成英语书法练习。
```

适合查询：

- 什么时间发生？
- 做过什么？

---

### Narrative View

描述：

这件事背后的故事。

Example:

```text
这次练字不仅是技能训练，
也是作者建立长期习惯的一次尝试。
```

适合查询：

- 为什么重要？
- 这件事情意味着什么？

---

### Growth View

描述：

个人成长变化。

Example:

```text
作者逐渐接受成长需要时间，
从结果导向转向过程导向。
```

适合查询：

- 我什么时候改变？
- 我什么时候成长？

---

### Identity View

描述：

长期身份变化。

Example:

```text
作者逐渐形成长期主义者身份。
```

适合查询：

- 我是什么样的人？
- 我的价值观是什么？

---

### Future Query View

描述：

未来可能如何被重新召回。

Example:

```text
用户未来可能询问：
什么时候开始变得自律？
```

# 5. Memory Write Pipeline

## 5.1 Chunking

Input:

```text
Long Diary Text
```

Output:

```text
Chunk[]
```

Chunk Metadata:

```json
{
  "chunk_id": "001",
  "date": "2026-07-20",
  "source": "diary"
}
```

---

## 5.2 Memory Extraction Agent

输入：

```text
Chunk Text
```

输出：

```json
{
  "views": [
    {
      "type": "growth",
      "content": "作者开始接受成长需要时间"
    },
    {
      "type": "identity",
      "content": "作者正在形成长期主义价值观"
    }
  ]
}
```

---

## 5.3 Embedding

每个 View 单独生成 embedding。

```text
Memory View
      │
      ▼
Embedding Model
      │
      ▼
Vector
```

---

# 7. Query Pipeline

## 7.1 Query Understanding

用户输入：

```text
我什么时候开始长期主义？
```

LLM 生成 Query Representation：

```text
寻找：

- 长期投入
- 稳定习惯建立
- 接受成长过程
- 从短期结果转向长期价值

可能相关经历：

学习
训练
生活习惯
自我管理
```

---

## 7.2 Query Embedding

```text
Query Representation
        │
        ▼
Embedding
```

---

## 7.3 ANN Retrieval

使用：

- HNSW
- FAISS
- ScaNN

流程：

```text
Query Vector
      │
      ▼
ANN Index
      │
      ▼
Top-K Memory Views
```

Example:

```text
View 1

Growth View

作者第一次接受成长需要时间。

----------------

View 2

Identity View

作者开始形成长期主义。

----------------

View 3

Event View

开始每天练习英语书法。
```

---

## 7.4 Candidate Aggregation

根据：

```text
chunk_id
```

聚合。

Example:

```text
Chunk 10001

Growth View

Identity View

Event View
```

---

## 7.5 Memory Reasoning

LLM 输入：

```text
User Query

+

Retrieved Views

+

Original Evidence
```

输出：

```text
回答

+

引用经历

+

可能的新洞察
```

# 8. Memory Evolution

系统长期运行过程中：

Memory 不应该静态。

流程：

```text
New Diary
    │
    ▼
New Memory View
    │
    ▼
Compare Existing Memory
    │
    ▼
Update User Model
```

Example:

Old:

```text
用户喜欢长期规划
```

New Evidence:

```text
用户开始接受变化
```

Update:

```text
用户价值观：

从控制未来

转向适应变化
```

# 9. Retrieval Optimization

## 9.1 Multi-stage Retrieval

不要直接：

Query -> Vector

采用：

```text
Query
 │
 ▼
Query Representation
 │
 ▼
ANN Retrieval
 │
 ▼

 │
 ▼

```

支持：

时间：

```text

```

类型：

```text

```

人物：

