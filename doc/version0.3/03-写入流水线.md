# v0.3 写入流水线（Memory Extraction）

## 1. 流程

```text
Chunk (SQLite)
    │
    ▼
Memory Extraction Agent (LLM)
    │
    ▼
views[] JSON
    │
    ├──> INSERT memory_views
    └──> embed + upsert diary_views (Chroma)
```

## 2. 模块

```
src/memory_extraction/
├── __init__.py
├── models.py      # MemoryViewDraft, ExtractionResult
├── agent.py       # extract_views_for_chunk()
└── prompt.py      # EXTRACTION_PROMPT
```

## 3. Extraction Agent 输出

输入：`{chunk_id, date, text}`

输出 JSON：

```json
{
  "views": [
    {"type": "event", "content": "今天完成英语书法练习。"},
    {"type": "growth", "content": "作者开始接受成长需要时间。"},
    {"type": "future_query", "content": "用户未来可能询问：什么时候开始接受成长需要时间？"}
  ]
}
```

## 4. Prompt 要点

- 不编造 chunk 外事实
- Growth / Identity 需有文本依据，可合理推断但不可无中生有
- Future Query 用「用户未来可能询问：…」句式
- 每 chunk **3–6** 条 view；至少 1 条 event（若有可描述事件）
- type 仅限：`event`, `narrative`, `growth`, `identity`, `future_query`

## 5. 离线脚本

```powershell
# 全量（仅无 view 的 chunk）
python scripts/build_memory_views.py

# 指定 chunk
python scripts/build_memory_views.py --chunk-id xxx

# 抽样试跑
python scripts/build_memory_views.py --ratio 0.05

# 强制重跑
python scripts/build_memory_views.py --force
```

## 6. 增量更新

| 触发 | 行为 |
|------|------|
| `ingest` / `update` 新 chunk | 手动或 `build_offline_cache.py --with-views` |
| chunk 文本变更 | `--force` 重提取该 chunk 的 views |

## 7. 失败与重试

- LLM JSON 解析失败：跳过该 chunk，记入日志
- 单条 view type 非法：丢弃该条，保留其余
- embed 失败：仍写 SQLite，Chroma 下次 `--sync-chroma` 补索引

## 8. 验收

对架构文档「英语书法」样例 chunk 人工抽检：

- 有 event + growth
- future_query 可被「长期主义/成长时间」类 query 语义召回
