# v0.3 验收与迁移

## 1. 测试 Query 集

| # | Query | 期望 need_retrieval | 期望主导算子 | 验收点 |
|---|-------|---------------------|--------------|--------|
| 1 | 我什么时候开始变得自律？ | true | view | growth/identity views 命中 |
| 2 | 碧莲做了什么 | true | tag | 实体召回 |
| 3 | 去年夏天我有什么成长 | true | tag+view | 双路有候选 |

| 6 | 你好 | false | — | conversation |

## 2. 手动验收步骤

```powershell
# 1. 构建 views（抽样）
python scripts/build_memory_views.py --ratio 0.1

# 2. Query Agent
python -m src.query_agent

# 3. 指定 scheme 试跑
$env:RETRIEVAL_SCHEME="tag_view_weighted"
python -m src.query "我什么时候开始长期主义"

# 4. Web 全链路
python main.py web
```

检查：

- `data/last_query.json` 含 query_representation
- `data/last_retrieval.json` 含 matched_views
- `data/last_context.json` 记忆块含「相关视角」

## 3. 迁移步骤

1. 部署代码，**默认 scheme 仍为 weighted_50_50**
2. 对 corpus 跑 `build_memory_views.py`（建议先 `--ratio 0.1` 试跑）
3. 切换 `RETRIEVAL_SCHEME=tag_view_weighted` 或改 config 默认
4. 跑完全部测试 query
5. 更新 `tool/tool.md`

## 4. 回滚

| 操作 | 效果 |
|------|------|
| `RETRIEVAL_SCHEME=weighted_50_50` | 回到 v0.2 行为 |
| `MEMORY_VIEWS_ENABLED=false` | ViewOperator 返回空 |

## 5. 性能基线

记录以下指标（验收前后对比）：

- 单轮 P95 延迟（含 Query Agent + 检索 + LLM）
- build_memory_views 每 chunk 耗时 / LLM token
- diary_views 条数 vs chunks 条数比值（目标 3–6x）

## 6. 已知限制（v0.3）

- 无 Memory Graph 关系推理
- 无 LLM Rerank
- View 质量依赖 Extraction prompt，需人工抽检
