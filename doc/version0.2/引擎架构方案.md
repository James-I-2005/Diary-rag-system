# Memory Retrieval Engine Architecture v0.1

## Design Goal

设计并实现一个 **Memory Retrieval Engine**。

Engine 本身不负责任何具体的检索逻辑，而是负责按照一份 Retrieval Plan 顺序执行多个 Operator，并维护 Candidate 的流转。

整个系统遵循以下原则：

- Engine 与具体算法完全解耦
- 每个检索算法都是独立 Operator
- Retrieval Strategy 仅由 Plan 决定
- 新增算法无需修改 Engine
- 未来支持任意 Pipeline 组合

例如：

```
Embedding

Tag -> Embedding

Embedding -> Tag

Tag -> Embedding -> Graph

Embedding -> Timeline -> Rerank
```

这些都应该只通过修改 Plan 完成，而无需修改 Engine。

---

# Core Components

整个架构仅包含四个核心概念：

```
Candidate
Operator
Plan
PlanExecutor
```

---

# Candidate

Candidate 是 Retrieval Pipeline 中唯一流动的数据对象。

所有 Operator 都只能：

```
CandidateSet -> CandidateSet
```

而不能直接依赖数据库中的 Diary Chunk。

建议数据结构：

```python
@dataclass
class Candidate:
    chunk_id: str
    score: float = 0.0
```

说明：

- chunk_id 为唯一标识
- score 为当前 Candidate 分数
- Candidate 保持轻量，不保存正文、Embedding、Metadata 等信息
- 如需其它数据，由对应 Operator 自行查询数据库

未来允许扩展：

```
source
reason
visited
trace
```

但当前版本无需实现。

---

# Operator

Operator 是一个独立、可插拔的检索算子。

统一接口：

```python
class Operator(ABC):

    @abstractmethod
    def execute(
        self,
        query: str,
        candidates: list[Candidate],
    ) -> list[Candidate]:
        ...
```

每个 Operator 只负责一件事情。

当前已有两个 Operator：

## EmbeddingOperator

职责：

- 根据 Query 进行向量召回
- 返回若干 Candidate

输入：

```
query
CandidateSet（可为空）
```

输出：

```
CandidateSet
```

---

## TagOperator

职责：

- 根据 Query 提取 Tag
- 基于 Tag 查询数据库
- 返回对应 Candidate

输入：

```
query
CandidateSet（可为空）
```

输出：

```
CandidateSet
```

注意：

Tag Operator 是独立召回，而不是 Embedding 的后处理。

未来可以继续增加：

```
GraphOperator
TimelineOperator
KeywordOperator
ImageOperator
RerankOperator
...
```

Engine 不需要任何修改。

---

# Plan

Plan 用于描述 Retrieval Pipeline。

Plan 本身不包含任何业务逻辑，仅描述 Operator 的执行顺序。

例如：

```python
Plan([
    EmbeddingOperator(),
    TagOperator(),
])
```

或者：

```python
Plan([
    TagOperator(),
    EmbeddingOperator(),
])
```

未来也可以支持：

```python
Plan([
    TagOperator(),
    GraphOperator(),
    EmbeddingOperator(),
])
```

Plan 是可替换、可组合的。

Engine 不应假设任何固定 Pipeline。

---

# PlanExecutor

PlanExecutor 是整个 Engine 的核心。

职责：

1. 接收 Query
2. 接收 Plan
3. 初始化 CandidateSet
4. 顺序执行每个 Operator
5. 将 CandidateSet 传递给下一 Operator
6. 返回最终 CandidateSet

执行流程：

```
Query
    │
    ▼
PlanExecutor
    │
    ▼
EmbeddingOperator
    │
    ▼
TagOperator
    │
    ▼
Final CandidateSet
```

伪代码：

```python
candidates = []

for operator in plan.operators:
    candidates = operator.execute(
        query=query,
        candidates=candidates,
    )

return candidates
```

PlanExecutor 不关心：

- Operator 类型
- Operator 内部算法
- 数据来源
- 检索方式

它只负责执行 Plan。

---

# Extensibility

新增任意 Retrieval Algorithm 时：

1. 新建一个 Operator
2. 实现 execute()
3. 将其加入 Plan

无需修改：

- Candidate
- PlanExecutor
- Engine

例如：

```
EmbeddingOperator
TagOperator
GraphOperator
TimelineOperator
ImageOperator
RerankOperator
```

都应遵循统一接口。

---

# Current Scope

当前仅实现：

- Candidate
- Operator 抽象类
- EmbeddingOperator
- TagOperator
- Plan
- PlanExecutor

暂不实现：

- Graph
- Timeline
- Rerank
- DAG Pipeline
- Planner
- 自动生成 Plan

当前目标是实现一个最小可运行（MVP）的可组合 Retrieval Engine，为未来增加更多 Operator 奠定基础。
