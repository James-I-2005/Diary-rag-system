# 第 09 章：测试验证与迭代优化

## 9.1 本章目标

建立可重复的测试流程，量化系统质量，指导 prompt 和参数调优。

验收：有 10+ 条测试用例；能自动跑检索/统计并对比期望结果。

## 9.2 为什么需要测试集

| 没有测试 | 有测试 |
|---------|--------|
| 「感觉好像对了」 | 知道检索召回率、计数准确率 |
| 改 prompt 后不知道是否变差 | 回归测试，改完跑一遍 |
| 无法向他人展示系统能力 | 有量化指标可演示 |

## 9.3 测试用例设计

`tests/test_queries.yaml`：

```yaml
# 检索型
- id: ret_food_01
  question: "这个月所有关于吃饭的内容"
  type: retrieval
  expect:
    min_results: 3
    must_contain_dates: ["2025-06-15"]   # 已知有吃饭内容的日期
    keywords_in_results: ["火锅", "饭团", "吃"]

- id: ret_friend_01
  question: "和朋友在一起的记录"
  type: retrieval
  expect:
    min_results: 1

# 统计型
- id: stat_touching_01
  question: "感动瞬间有多少次"
  type: statistical
  expect:
    metric: touching_moments
    count_min: 1          # 至少 1 次（根据你的真实日记调整）
    count_max: 20

- id: stat_hotpot_01
  question: "吃了几次火锅"
  type: statistical
  expect:
    count_min: 0
    count_max: 10

# 归纳型
- id: sum_activity_01
  question: "这个月最喜欢做的事情是什么"
  type: summarization
  expect:
    top_activity_contains: ["散步", "火锅", "看电影"]  # 任一词出现在 top 3

# 边界情况
- id: edge_empty_01
  question: "我去火星旅行的记录"
  type: retrieval
  expect:
    max_results: 0

- id: edge_classify_01
  question: "有没有让人感动的时候"
  type: statistical
  expect:
    metric: touching_moments
```

设计原则：
- 覆盖三类查询各至少 3 条
- 包含你知道正确答案的「金标准」用例
- 包含边界情况（无结果、跨类型）

## 9.4 自动化测试脚本

`tests/run_tests.py`：

```python
"""运行 test_queries.yaml 中的测试用例。"""

import yaml
from pathlib import Path
from src.query import query, classify_query


def load_tests() -> list[dict]:
    path = Path(__file__).parent / "test_queries.yaml"
    with open(path, encoding="utf-8") as f:
        return yaml.safe_load(f)


def check_retrieval(result: dict, expect: dict) -> list[str]:
    errors = []
    chunks = result.get("chunks", [])
    count = len(chunks)

    if expect.get("min_results") and count < expect["min_results"]:
        errors.append(f"结果数 {count} < 期望最少 {expect['min_results']}")
    if expect.get("max_results") is not None and count > expect["max_results"]:
        errors.append(f"结果数 {count} > 期望最多 {expect['max_results']}")

    dates = {c["date"] for c in chunks}
    for d in expect.get("must_contain_dates", []):
        if d not in dates:
            errors.append(f"缺少期望日期 {d}")

    all_text = " ".join(c["text"] for c in chunks)
    for kw in expect.get("keywords_in_results", []):
        if kw not in all_text:
            errors.append(f"结果中未找到关键词 '{kw}'")

    return errors


def check_statistical(result: dict, expect: dict) -> list[str]:
    errors = []
    count = result.get("count", -1)

    if expect.get("metric") and result.get("metric") != expect["metric"]:
        errors.append(f"指标 {result.get('metric')} != 期望 {expect['metric']}")
    if expect.get("count_min") is not None and count < expect["count_min"]:
        errors.append(f"计数 {count} < 最小期望 {expect['count_min']}")
    if expect.get("count_max") is not None and count > expect["count_max"]:
        errors.append(f"计数 {count} > 最大期望 {expect['count_max']}")

    return errors


def check_summarization(result: dict, expect: dict) -> list[str]:
    errors = []
    top_acts = [a for a, _ in result.get("top_activities", [])]
    expected_any = expect.get("top_activity_contains", [])
    if expected_any and not any(a in top_acts for a in expected_any):
        errors.append(f"top activities {top_acts} 未包含期望词 {expected_any}")
    return errors


def run_all():
    tests = load_tests()
    passed = failed = 0

    for t in tests:
        tid = t["id"]
        question = t["question"]
        expected_type = t.get("type")
        expect = t.get("expect", {})

        actual_type = classify_query(question)
        result = query(question)

        errors = []
        if expected_type and actual_type != expected_type:
            errors.append(f"分类 {actual_type} != 期望 {expected_type}")

        if result["type"] == "retrieval":
            errors.extend(check_retrieval(result, expect))
        elif result["type"] == "statistical":
            errors.extend(check_statistical(result, expect))
        elif result["type"] == "summarization":
            errors.extend(check_summarization(result, expect))

        if errors:
            print(f"❌ {tid}: {question}")
            for e in errors:
                print(f"   - {e}")
            failed += 1
        else:
            print(f"✅ {tid}")
            passed += 1

    print(f"\n结果: {passed} 通过, {failed} 失败, 共 {len(tests)} 条")


if __name__ == "__main__":
    run_all()
```

运行：

```bash
python tests/run_tests.py
```

## 9.5 评估指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 分类准确率 | 问题类型判对比例 | > 90% |
| 检索召回率 | 金标准相关 chunk 被召回比例 | > 80% |
| 统计准确率 | 计数与人工核对一致 | 100% |
| 引用正确率 | 回答中的日期确实来自对应 chunk | > 95% |

### 人工评估表

对 10 条回答打分（1–5）：

| 问题 | 相关性 | 完整性 | 引用准确 | 语言自然 | 备注 |
|------|--------|--------|---------|---------|------|
| 吃饭内容 | 4 | 3 | 5 | 4 | 漏了一条便利店 |

## 9.6 迭代优化清单

按收益排序：

### 1. 标签提取 prompt（影响最大）

- 抽查 20 条 `chunk_tags`，统计字段准确率
- 针对错误类型加 few-shot 示例
- 重新 `extract_all_tags()` 后跑测试

### 2. 切块参数

- `max_chars` 从 500 调到 400 或 600，看检索 recall 变化
- 检查是否在句子中间切断

### 3. 检索 top_k

- 太小漏结果，太大引入噪声
- 对检索型测试用例扫一遍 top_k = 10, 20, 30

### 4. 问题分类规则

- 收集分类错误的 case，补充关键词
- 考虑「有没有」归入 statistical

### 5. 回答 prompt

- 统计型：强调「不要改数字」
- 检索型：强调「无内容就说没有」
